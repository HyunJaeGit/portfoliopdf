프론트엔드·웹디자인 전체 페이지 검토 피드백
작성일: 2026-08-23

1. 검토 범위와 방법

프로덕션 빌드 결과를 로컬에서 실행하고 다음 라우트를 데스크톱 1440px와 모바일 390px 크기로 직접 렌더링해 순회했다.

- 홈 /
- 이력서 /resume
- 포트폴리오 /portfolio
- Aura3D /portfolio/aura3d
- MZ /portfolio/mz
- 전체 PDF /print
- 404 /missing-page

검토 기준은 시각적 계층, 레이아웃 균형, 반응형 전환, 정보 밀도, 텍스트 판독성, 이미지 활용, 내비게이션, 접근성, 페이지 간 디자인 일관성이다. 점검용 캡처는 페이지 전체를 보기 위해 실제 콘텐츠보다 긴 고정 높이로 생성했으므로 캡처 하단의 큰 공백은 사이트 결함으로 판단하지 않았다.

2. 전체 평가

현재 디자인은 ‘백엔드 기술 사례집’이라는 콘셉트가 명확하다. 버건디·네이비·아이보리 색상, 문서 번호, 얇은 구분선, 영문 레이블과 모노스페이스 글꼴이 페이지 전반에서 일관되게 사용된다. 일반적인 카드형 개발자 포트폴리오보다 인쇄물·기술 보고서에 가까운 개성이 있으며, Aura3D와 MZ 상세 페이지가 같은 문법으로 구성돼 비교하기 쉽다.

전면적인 리디자인은 필요하지 않다. 우선 개선할 부분은 모바일 헤더, 작은 보조 글자, 모바일 상세 이미지 판독성, 긴 페이지의 탐색 보조, 전체 PDF 화면의 중복 콘텐츠 안내다. 기존 구조와 색상은 유지하면서 반응형과 읽기 편의성을 보완하는 방향이 적합하다.

3. 우선순위 요약

[P1: 먼저 확인·수정 권장]

3-1. 모바일 헤더에서 메뉴 버튼 노출 확인
- 390px 실제 렌더링 캡처에서는 로고와 ‘전체 PDF’ 버튼은 보이지만 메뉴 버튼이 화면에 나타나지 않았다.
- CSS상 메뉴 버튼은 720px 이하에서 표시되도록 되어 있으므로 header-actions의 실제 너비, flex 축소, 화면 밖 overflow 여부를 브라우저 개발자 도구에서 확인해야 한다.
- 권장: 모바일에서 ‘전체 PDF’를 메뉴 안으로 이동하거나 짧은 아이콘 버튼으로 바꾸고, 헤더에는 로고와 메뉴 버튼만 남긴다.
- 최소 대안: .site-title과 .header-actions에 min-width: 0을 지정하고, 메뉴 버튼에 flex: none을 적용한 뒤 320px·360px·390px에서 확인한다.

3-2. 0.62~0.72rem 보조 글자의 모바일 판독성
- 문서 번호, 영문 레이블, 기간, 캡션과 기술 목록에 0.62~0.72rem 크기가 반복된다.
- 데스크톱에서는 장식적 계층으로 작동하지만 모바일에서는 화면 축소와 긴 한글 문장이 겹치며 읽기 부담이 커진다.
- 권장: 모바일에서 주요 보조 정보는 최소 0.75rem, 본문 성격의 설명은 0.8rem 이상을 기준으로 조정한다. 단순 CASE 번호와 짧은 영문 레이블만 현재 크기를 유지한다.
- 제목 크기는 현재도 충분하므로 키우지 않아도 된다.

3-3. 상세 이미지의 모바일 판독성
- Aura3D 아키텍처·ERD와 MZ ERD는 모바일에서 이미지 전체가 축소돼 내부 글자를 읽기 어렵다.
- 단순히 이미지 높이를 키우면 세로 길이만 늘고 글자 판독성은 크게 좋아지지 않는다.
- 권장: 이미지를 누르면 원본을 새 화면 또는 라이트박스로 확대해 볼 수 있게 하고 ‘확대해서 보기’ 텍스트를 제공한다.
- 서버 기능 없이 정적 링크와 dialog만으로 구현할 수 있다. 새 이미지를 만들거나 내용을 임의로 재구성할 필요는 없다.

[P2: 완성도 개선]

3-4. 긴 상세 페이지의 현재 위치 표시
- 챕터 바로가기는 있으나 스크롤 후에는 상단에서 멀어지고 현재 읽는 챕터를 표시하지 않는다.
- 권장: 데스크톱에서는 간단한 sticky 챕터 목록, 모바일에서는 접을 수 있는 ‘목차’ 버튼 또는 섹션 상단 복귀 링크를 검토한다.
- 현재 헤더가 sticky이므로 추가 sticky UI가 화면을 과하게 차지하지 않도록 한 가지만 사용한다.

3-5. 링크와 버튼의 시각적 역할 구분
- 버건디 텍스트 링크, 테두리 버튼, 카드 전체 링크가 함께 사용되지만 일부 CTA는 크기가 작아 본문 레이블처럼 보인다.
- 권장: 주요 행동은 테두리 버튼, 페이지 이동은 화살표 텍스트 링크, 카드 진입은 카드 전체 hover/focus 스타일로 역할을 고정한다.
- 특히 포트폴리오 카드의 ‘상세 포트폴리오 보기’는 hover와 keyboard focus에서 카드 전체가 반응한다는 점을 더 분명하게 보여주는 것이 좋다.

3-6. 반복되는 아주 작은 메타 정보 정돈
- 역할·기간·기술·구분을 여러 영역에서 반복해 신뢰도는 높지만 화면이 촘촘하게 느껴질 수 있다.
- 권장: 홈은 핵심 결과와 역할, 포트폴리오 목록은 역할·핵심 구현, 상세는 전체 기술과 기간처럼 페이지마다 정보 책임을 구분한다.
- 정보를 삭제하기보다 같은 문장을 반복하지 않도록 요약 수준을 달리한다.

4. 공통 영역 검토

4-1. 헤더와 내비게이션

좋은 점
- 데스크톱 헤더는 높이가 작고 문서형 화면을 방해하지 않는다.
- 현재 메뉴의 버건디 밑줄과 focus-visible 처리가 명확하다.
- ‘전체 PDF’가 항상 노출돼 포트폴리오의 목적과 잘 맞는다.

보완점
- 모바일 캡처에서 메뉴 버튼이 확인되지 않은 문제를 가장 먼저 재현해야 한다.
- ‘전체 PDF’와 ‘메뉴’가 함께 들어가면 320px에서 헤더가 혼잡해질 가능성이 있다.
- 모바일 메뉴가 열렸을 때 바깥 영역 클릭 닫기와 메뉴 항목 선택 후 닫기를 명시적으로 처리하면 완성도가 높아진다.

권장안
- 데스크톱: 현재 유지.
- 모바일: 로고 / 메뉴 버튼 두 영역으로 단순화하고 전체 PDF는 펼친 메뉴의 첫 번째 또는 마지막 항목으로 이동.

4-2. 색상과 타이포그래피

좋은 점
- 버건디는 강조와 행동, 네이비는 제목과 결과 영역에 일관되게 사용된다.
- 배경 아이보리가 순백색보다 인쇄물 같은 인상을 만든다.
- 한글 본문과 영문 기술 레이블의 서체 역할이 명확하다.

보완점
- 작은 회색 캡션과 기술 문자열은 모바일에서 대비보다 크기가 먼저 문제가 된다.
- 한 줄에 많은 기술을 가운데점으로 연결하면 작은 화면에서 스캔하기 어렵다.

권장안
- 기술 문자열은 모바일에서 줄바꿈 가능한 inline 목록이나 짧은 태그 묶음으로 표현하되, 테두리와 배경을 많이 추가해 기존 문서형 분위기를 깨지 않는다.
- 본문 크기는 유지하고 캡션·메타 텍스트만 선택적으로 상향한다.

4-3. 여백과 콘텐츠 폭

좋은 점
- 데스크톱 최대 폭 1080px은 긴 한글 문장과 이미지의 균형이 좋다.
- 섹션 사이 여백이 명확해 정보량이 많아도 장별 구분이 된다.

보완점
- 모바일 상세 페이지는 섹션이 길게 연속돼 챕터 경계가 약하게 느껴질 수 있다.
- 구분선만 반복하기보다 챕터 번호·제목 주변 여백을 일정하게 유지하는 것이 중요하다.

권장안
- 화면용 전역 여백을 일괄 축소하지 않는다.
- 모바일에서 챕터 상단 여백은 유지하고, 카드 내부 padding과 리스트 간격만 소폭 줄인다.

5. 페이지별 검토

5-1. 홈

좋은 점
- 첫 화면에서 이름, 직무, 대표 수치, 이력서·포트폴리오 행동이 바로 보인다.
- 버건디 Hero가 다른 페이지의 밝은 배경과 대비돼 표지 역할을 잘한다.
- 역량 → 프로젝트 → 실무 경험 순서가 자연스럽다.

보완점
- 모바일 Hero의 설명과 연락처가 한 화면에 밀집돼 버튼 아래가 조금 답답하다.
- 역량 카드의 영문 스택이 작고 길어 모바일에서 읽기 어렵다.
- 프로젝트 미리보기와 포트폴리오 목록의 정보가 상당 부분 반복된다.

제안
- 모바일 Hero에서는 연락처와 CTA 사이 간격을 조금 늘리거나 GitHub·이메일을 한 줄씩 명확히 분리한다.
- 역량 카드의 stack은 0.75~0.78rem로 높이고 기술군 단위 줄바꿈을 허용한다.
- 홈 프로젝트는 ‘수치/대표 강점 + 한 줄 역할’까지만 보여주고 상세 기술 목록은 포트폴리오로 넘긴다.

5-2. 이력서

좋은 점
- 데스크톱 2열 구조는 경력·교육과 기술·프로젝트를 효과적으로 분리한다.
- 핵심 역량 3개가 상단에 있어 긴 이력서를 빠르게 파악할 수 있다.
- 프로젝트에서 수치와 역할을 먼저 보여주도록 수정된 순서가 좋다.

보완점
- 데스크톱에서도 본문과 기간 글자가 작은 편이며, 모바일에서는 많은 정보가 긴 단일 열로 이어진다.
- 모바일에서 핵심 역량, 경력, 교육, 기술, 프로젝트, AI 항목 사이의 계층 차이가 데스크톱보다 약해진다.
- ‘상세 포트폴리오 보기’가 작은 텍스트 링크라 긴 페이지에서 놓치기 쉽다.

제안
- 모바일 본문·목록은 최소 0.78~0.8rem, line-height 1.55 전후로 조정한다.
- 모바일의 resume-heading 위쪽 간격을 조금 늘려 큰 섹션 전환을 강조한다.
- 상세 포트폴리오 링크는 폭 전체 버튼으로 만들 필요는 없지만 상하 padding을 늘려 터치 영역을 확보한다.
- 인쇄용 8.5pt 설정은 화면 CSS와 분리돼 있으므로 그대로 유지한다.

5-3. 포트폴리오 목록

좋은 점
- 검은 문서 바가 전체 폭으로 맞춰져 안정적이다.
- 소개 문단 대신 실제 프로젝트 목차가 배치돼 목적이 더 명확하다.
- 각 카드가 이미지, 역할, 핵심 구현, 기술, 배경 순으로 구성돼 강점이 먼저 보인다.

보완점
- 데스크톱 카드의 설명 글자가 촘촘하고 한 카드 안에서 메타 정보가 많다.
- 모바일에서 기술 목록과 프로젝트 배경이 연속되며 카드가 길어진다.
- 이미지 비율은 안정적이지만 두 프로젝트의 시각적 색감 차이가 커 카드 높이와 무게가 다르게 느껴질 수 있다.

제안
- 목록에서는 기술을 핵심 4~5개로 제한하고 전체 스택은 상세 페이지에서 제공한다.
- 모바일에서는 프로젝트 배경을 2~3줄로 제한할지 검토하되 중요한 내용이 잘리지 않도록 ‘상세에서 계속’ 구조로 연결한다.
- 카드 hover/focus 시 배경색과 좌측 또는 상단 강조선 중 하나를 사용해 클릭 가능성을 강화한다.

5-4. Aura3D 상세

좋은 점
- 다중 URL 관리에서 출발해 스캔 제어, 상태 비교, 조건부 AI, 3D 표현으로 확장되는 흐름이 명확하다.
- 약 90% 수치가 상단에 있어 프로젝트 강점을 빠르게 파악할 수 있다.
- 아키텍처, 구현 목록, ERD, API 사용량 캡처가 주장과 연결된다.

보완점
- 데스크톱에서도 구현 목록과 이미지가 많아 한 챕터의 밀도가 높다.
- 모바일에서 아키텍처와 ERD 내부 글자를 읽기 어렵다.
- ‘약 90%’의 측정 조건은 화면에서 바로 보이지 않아 수치의 근거를 사용자가 캡션에서 추론해야 한다.

제안
- 아키텍처·ERD 이미지에 확대 보기 기능을 우선 추가한다.
- 수치 아래에 ‘반복 상태 테스트 기준’ 같은 짧은 조건을 함께 표시한다.
- 구현 6개 항목은 모바일에서 accordion으로 숨기기보다 현재처럼 모두 보여주되 번호·제목 대비를 조금 높인다.
- 결과 섹션에 ‘한계/다음 개선’ 한 항목을 추가하면 기술 판단의 깊이가 더 잘 드러난다. 실제 확인된 내용만 작성한다.

5-5. MZ 상세

좋은 점
- 강화된 첫 설명에서 4인 팀장, Oracle·MyBatis, 검색·지도·배포의 전체 범위가 이전보다 선명하다.
- 메인 화면 → 데이터/회원가입 → 지도 → 배포 순서가 서비스 흐름과 일치한다.
- 본인 기여와 팀 구현 범위를 나눈 표가 신뢰도를 높인다.

보완점
- Aura3D보다 상단의 대표 성과가 정성적으로 보인다. ‘4인’, ‘2개 검색축’, ‘2계층’은 사실을 전달하지만 기술적 강도를 바로 보여주지는 못한다.
- 데이터·검색 챕터의 ERD와 회원가입 이미지가 모바일에서 연속으로 크게 배치돼 페이지가 길어진다.
- 마지막 배포·기여 영역은 정보량이 많지만 시각적 결론이 약하다.

제안
- 상단 핵심 수치는 현재처럼 검증 가능한 범위만 유지하되 ‘전체 SQL 작업 전담’을 수치 카드 옆 핵심 역할 문장으로 강조한다.
- 모바일의 ERD와 회원가입 이미지는 가로 슬라이더보다 세로 배치를 유지하고 각각 확대 보기를 제공한다.
- 마지막에 ‘데이터 모델 → SQL → 지도 → AWS 배포’ 네 단계 요약을 한 줄 흐름으로 추가하면 프로젝트 전체를 다시 묶어줄 수 있다.
- 팀 기여 표의 모바일 제목은 현재 의사 요소보다 실제 heading 텍스트가 접근성과 유지보수에 더 유리하다.

5-6. 전체 PDF 화면

좋은 점
- PDF에 포함되는 범위를 상단에서 설명하고 이미지와 폰트 로딩을 기다린 뒤 인쇄한다.
- 화면상 각 문서가 순서대로 이어져 출력 전에 내용을 확인할 수 있다.

보완점
- 모바일에서는 전체 문서가 한 화면에 모두 렌더링돼 매우 길고, 인쇄 버튼을 누른 뒤 결과를 기다리는 동안 상태 안내가 없다.
- 홈, 이력서, 목차, 상세에 프로젝트 설명이 반복된다.
- 일반 화면용 미리보기와 실제 인쇄 페이지 분할이 달라 사용자가 최종 분량을 예측하기 어렵다.

제안
- 상단에 ‘예상 15페이지’와 포함 항목을 표시하되 콘텐츠 변경 시 수동 숫자가 낡지 않도록 주의한다.
- 인쇄 버튼을 누르면 ‘이미지와 글꼴을 준비 중’ 상태를 표시하고 중복 클릭을 막는다.
- 모바일에서는 각 문서 미리보기를 접을 수 있게 하거나 ‘PDF 출력은 데스크톱 권장’ 안내를 제공한다.
- 제출용 PDF를 더 짧게 만들고 싶다면 전체 PDF에서만 홈의 역량·프로젝트 반복 영역을 숨기는 방법이 가장 효과적이다.

5-7. 404 페이지

좋은 점
- 오류 코드, 설명, 홈 링크가 명확하고 불필요한 요소가 없다.
- 기존 색상과 타이포그래피를 그대로 사용한다.

보완점
- 넓은 화면과 모바일 모두 콘텐츠가 상단에만 작게 위치해 의도적으로 완성된 오류 화면보다는 기본 안내처럼 보인다.

제안
- 최소 높이를 확보해 콘텐츠를 화면 중앙에 가깝게 배치한다.
- ‘홈으로 이동’ 외에 ‘포트폴리오 보기’를 보조 링크로 추가한다.
- 장식은 현재 문서형 디자인에 맞는 큰 404 번호나 짧은 구분선 정도로 제한한다.

6. 접근성·상호작용 검토

현재 확인된 좋은 요소
- 본문 건너뛰기 링크
- 키보드 focus-visible
- 이미지 대체 텍스트와 figure/figcaption
- 의미 있는 heading 구조
- reduced-motion 대응
- 모바일 메뉴의 aria-expanded와 Escape 닫기

추가 확인 권장
- 모바일 메뉴가 320~390px에서 실제 노출되고 키보드 포커스 순서에 포함되는지 확인
- 전체 카드 링크의 focus 상태가 카드 영역 전체에서 충분히 보이는지 확인
- 이미지 확대 기능을 추가할 경우 Escape 닫기, 포커스 이동·복귀 구현
- muted 텍스트와 아이보리 배경의 명도 대비를 자동 도구로 측정
- 200% 브라우저 확대에서 가로 스크롤과 텍스트 잘림 확인

7. 권장 실행 순서

1단계: 모바일 기본 사용성
- 모바일 헤더 메뉴 노출 문제 재현 및 수정
- 모바일 보조 글자 크기 조정
- 주요 링크 터치 영역 확인

2단계: 프로젝트 증거 판독성
- ERD·아키텍처 이미지 확대 보기
- 이미지 캡션과 측정 조건 연결
- 카드 hover/focus 피드백 강화

3단계: 긴 페이지 탐색
- 상세 페이지 현재 챕터 또는 상단 복귀 기능
- 전체 PDF 준비 상태 표시
- 404 화면의 시각적 완성도 보완

4단계: 중복 정보 정리
- 홈·목록·상세의 정보 책임 분리
- PDF에서만 반복 영역 축약 여부 결정

8. 유지해야 할 요소

- 버건디·네이비·아이보리 색상 체계
- 문서 바, CASE 번호, 얇은 구분선 중심의 사례집 콘셉트
- 최대 폭 1080px의 데스크톱 구성
- Aura3D와 MZ가 같은 구조로 비교되는 상세 레이아웃
- 본인 기여와 팀 구현 범위를 구분하는 방식
- 화면과 인쇄 CSS를 분리한 구조
- 과도한 애니메이션과 장식이 없는 현재 방향

9. 결론

현재 사이트는 전면 수정이 필요한 상태가 아니라, 완성된 디자인 시스템에 반응형 세부 조정을 더하면 되는 단계다. 가장 중요한 개선은 모바일에서 내비게이션을 확실히 사용할 수 있게 하는 것과 작은 보조 텍스트 및 기술 이미지를 읽기 쉽게 만드는 것이다. 그다음으로 긴 상세 페이지의 탐색과 PDF 준비 상태를 보완하면 사용자 경험이 안정된다. 색상, 문서형 레이아웃, 프로젝트 상세 구조는 현재 포트폴리오의 차별점이므로 유지하는 편이 좋다.
